How These Were Obtained

TIMA TrustZone leaks physical addresses in dmesg accessible from shell (UID 2000). Physical-to-virtual conversion: vaddr = paddr + 0xA0000000. Firmware symbol table from Samsung GPL kernel source at github.com/Exynos3475/android_kernel_samsung_exynos3475 (branch clean_base).

Exploitation Implications

  • With arbitrary write: overwrite selinux_enforcing (0xC0B7AD18) to 0 → disable SELinux
  • With code execution in kernel: call prepare_kernel_cred(0) → commit_creds() → instant root
  • No PXN: userspace shellcode can run directly in kernel context
  • TIMA caveat: monitors selinux_enforcing every 5 min — must neutralize or race TIMA

What This Means For Exploitation

The kernel has 4 major protections OFF that modern kernels typically have. This is an extremely favorable target.

  • No KASLR → all kernel addresses are known and static (see table above)
  • No PXN → can map shellcode in userspace and jump to it from kernel — ret2user works
  • No stack canaries → stack buffer overflows give direct PC control (no info leak needed)
  • No HARDENED_USERCOPY → copy_to/from_user won't bounds-check, enabling arbitrary kernel read/write
  • mmap_min_addr=0x8000 → can map at low addresses for null-deref exploitation (map at 0x8000+)

Active Defenses To Bypass

  • SELinux (Enforcing) — fully analyzed policy, 10,896 rules parsed. CONFIRMED dead end for policy-based bypass. Must disable via kernel write to selinux_enforcing
  • TIMA TrustZone — Samsung integrity monitor in secure world. Checks kernel code + SELinux status every 5 min. Any modification detected → device lockdown. Must race or neutralize
  • kptr_restrict — /proc/kallsyms shows 0x00000000. Bypassed via TIMA paddr leak in dmesg
  • panic_on_oops=1 — any kernel oops → panic → ramdump. Must be precise, no trial-and-error
